# AGENTS.md

> Agent-facing contributor guide (architecture decisions, gotchas, conventions). Product intro & user docs live in README.md and the web docs page — don't duplicate them here.

Multi-agent collaboration hub: agents register their workspaces (opencode, claude code, …) to a central server and ask each other for help. Single FastAPI service (`server/`) that hosts the management REST API, the MCP endpoint, and plugin distribution; per-agent plugins under `plugins/`; a React 19+Vite SPA (`web/`). Repo docs/comments and TODO.md are written in Chinese.

## Layout
- `server/` — FastAPI app, entry `server/main.py:app`. Routes: `/mcp` (MCP Streamable HTTP, API-key auth), `/api/*` (JWT auth except `/api/auth/*`), `/a2a/{workspace_id}` + `/.well-known/agent-card.json` (A2A JSON-RPC gateway, apikey auth), `/download/*` (unauthenticated plugin distribution), `/health`. Channel gateways: `server/feishu/` (Feishu cards/timeline) and `server/weixin/` (WeChat ClawBot, `/api/weixin/*` QR-scan login; no server-side env config — one bot per user).
- `plugins/opencode/` — opencode plugin (TS, entry `src/index.ts`, default-export `Plugin`). Deployed to `~/.config/opencode/plugins/agent-swarm/src/index.ts`. **Heartbeat + task execution**: reads WORKSPACE_ID from the project's `.agent_swarm/workspace.md`, heartbeats every 30s (with session id + title), and receives A2A tasks over the nexus WS (`src/nexus_a2a.ts`). It injects NO tools — all agent-facing operations live in the server's MCP tool set.
- `plugins/claude/` — claude code integration. `keepalive.mjs` is a **zero-dependency local stdio MCP server** (minimal hand-rolled JSON-RPC: answers `initialize`/`ping`/`tools:list` only) that claude spawns as an MCP subprocess; on spawn it starts a 30s heartbeat loop (`agent_type=claude`), reading WORKSPACE_ID from `process.cwd()/.agent_swarm/workspace.md` each cycle. Exit: stdin close + ppid poll fallback → workspace goes offline via the server's 90s timeout. Plus `commands/` (`/swarm-*` md for `~/.claude/commands/`) and `install-claude.sh|.ps1`. claude workspaces are **registration/keepalive only** — the A2A gateway rejects them server-side (`nexus_a2a.py`).
- `web/` — SPA, dev server :8701 proxying `/api /download /mcp /health` → :8700.
- `deploy/` — `start`/`stop` scripts (sh + ps1) and **installer dispatchers** (`install.sh`/`install.ps1`): download `plugin.tar.gz` (now contains the whole `plugins/` tree), extract to a temp dir, and run each `plugins/<name>/install-<name>.sh|.ps1` with `--server/--api-key/--src` passed through (`--only`/`-Only` filters).
- `docker/` — Dockerfile (multi-stage: node builds web → python runtime) + compose.yaml. Build-verified 2026-09-14.

## Commands
```bash
./deploy/start.sh [port]     # server on :8700 (default). Creates .venv, installs requirements.txt,
                             # tarballs plugins/ -> data/agent-swarm-plugin.tar.gz, and FOREGROUND runs
                             # uvicorn (Ctrl-C stops). Idempotent: exits if /health already OK.

./deploy/stop.sh [port]
cd web && npm run dev        # vite :8701
cd web && npm run build      # tsc -b && vite build

```

## Server facts
- **All agent-facing operations are MCP tools in `server/mcp_endpoint.py`** (`@mcp.tool()`), 11 total: `workspace_add/remove/enable/disable/offline`, `heartbeat`, `update_notes/info`, `list_workspaces`, `a2a_call`, `a2a_task`. Auth: `ApiKeyMiddleware` validates `Authorization: Bearer <apikey>` on every `/mcp` request and stores the user in a contextvar; tools read it via `get_user()`.
- The intended client is ANY MCP client: opencode connects via `mcp.agent-swarm` (remote URL + Bearer header) written into `opencode.jsonc` by the install scripts; claude/deepseek harnesses can connect the same way. This portability was an explicit user decision (2026-09-12) — do not move tools back into the plugin.
- Workspace ID persistence: `workspace_add` returns the ID, the calling agent writes it to `.agent_swarm/workspace.md` (`WORKSPACE_ID:` line) in the project root; the plugin reads that file every heartbeat cycle. `register_workspace`/`workspace_whoami` were deliberately removed — don't reintroduce them.
- **A2A protocol (2026-09-14, replaces workspace_call/nexus 自定义协议)**: `server/nexus_a2a.py` is a hand-written A2A 0.3.x subset (JSON-RPC over HTTP, NO official SDK — deliberate, mirrors keepalive.mjs philosophy). Endpoints: `GET /.well-known/agent-card.json` (hub card), `GET/POST /a2a/{workspace_id}` (per-workspace Agent Card + `message/send`, `message/stream` SSE, `tasks/get`, `tasks/cancel`). Objects are spec-shaped camelCase (`TaskState`, `kind: "status-update"/"artifact-update"`, `input-required` for permission/question). Verify interop with a2a-inspector if in doubt.
- **Internal transport is still WS**: plugin connects `/ws/plugin` (apikey hello), server pushes `{"type":"rpc","payload":<JSON-RPC request>}`; plugin answers `{"type":"rpc","id",...}` + streams `{"type":"event","payload":<A2A event>}`. Additionally `{"type":"monitor","payload":{roundKey,type,...}}` carries foreground-session monitoring events (see Monitor facts below). Queued tasks are flushed to the plugin on WS connect (no more heartbeat piggybacking — heartbeat now only keeps alive + reports session id/title). Web subscribes via `/ws/nexus` (JWT hello) and sends tasks via REST `POST /api/nexus/{wid}/message:send`, replies to input-required via `POST /api/nexus/{wid}/reply`, clears via `DELETE /api/nexus/{wid}/history`.
- **Multiple plugin connections per workspace (2026-09-23)**: `plugins[wid]` is a **list**, not a single slot — every connection registers and stays, and the old "new replaces old, close 4001" kick is GONE. Reason: two opencode instances in the same project dir read the same `workspace.md`, so both claimed one `wid`; the single-slot kick + the client's unconditional 1s reconnect made them kick each other **once per second forever** (15222 connects, only 9 natural disconnects) and froze the service. Now both stay connected and both stream `monitor`/`event` (so briefs/monitoring sync from every instance). Task dispatch and input-required replies use `primary_conn(wid)` = first *fresh* connection (fallback: list head); on send failure the dead conn is dropped and the next is tried. Replies route back by the connection's OWN reported session — plugins send `{"type":"session","session_id":...}` on `hello_ok` and whenever the foreground session changes; `conn_for_session(wid, sid)` matches on it. **Do NOT** use `workspaces.session_id` to pick a connection: it's overwritten by whichever instance heartbeats last. `_flush_queued` only fires on the 0→1 connection transition (no double-dispatch).
- **External A2A agents**: `a2a_call(target, message)` accepts a workspace ID OR an external endpoint URL (http(s)); external tasks land in the same `a2a_tasks` table (`external_url` set, `workspace_id` empty) and are polled via `a2a_task`. Outbound calls are non-streaming `message/send` via httpx.
- REST mirror for call records: `/api/calls` (list, `?workspace_id=` filter) + `DELETE /api/calls/{id}` (only terminal states, ownership checked, monitor rounds cascade-delete their events). Timeout: `AGENT_SWARM_CALL_TIMEOUT` (default 1h), enforced in `_wait_final`/SSE generator/a2a_task lazily.
- **Artifacts (2026-09-22)**: agents upload output files via MCP `artifact_upload` (12th tool) → one-time signed `upload_url` (10 min, single-use) → agent `curl -F file=@path` raw multipart (NO base64 — decision: keep binary bytes out of JSON). REST: `GET /api/artifacts` + `PUT {id}/pin` + `DELETE {id}` (JWT), `POST /api/artifacts/upload?nonce=&token=` (one-time token, no JWT), `GET {id}/download?token=` (HMAC-signed, 30d, no JWT — IM/browser clicks can't send headers). Storage `data/artifacts/<id>_<name>`, TTL 7 days (`AGENT_SWARM_ARTIFACT_TTL_DAYS`, max size `AGENT_SWARM_ARTIFACT_MAX_MB` default 20) with hourly GC in main.py lifespan (pinned rows never auto-deleted). On upload the server pushes to Feishu (im.v1.file.create → file message; falls back to text link) + Weixin (tries file item type-2, known-unverified; falls back to text link) per the brief-push rule (owner's brief_on chats). Upload token sigs live in `server/artifacts.py`; request base URL for absolute links is derived per-request (PUBLIC_URL → x-forwarded-* → host) — in MCP tools read contextvar `current_base_url` (set by ApiKeyMiddleware).
- **Event bus**: in-process `_task_queues` (asyncio.Queue per subscriber) drives SSE and sync waiters — no polling. Events are persisted in `a2a_events` (web history replay caps at 800).
- **Monitor (2026-09-15, foreground-session live monitoring)**: plugin streams TUI conversation rounds as `{"type":"monitor","payload":{roundKey,sessionId,type:text/reasoning/tool/user/user-text/permission/question/idle/replied,...}}` over the plugin WS; `handle_monitor_event` persists them in `a2a_events` (kind="monitor", `round_key` column = `mon-<sid>-<msgid>`) AND auto-creates/updates a round row in `a2a_tasks` (caller="monitor") so the calls page and reply endpoint work unchanged. Round states: permission/question → input-required; replied → working; idle → completed (even with pending permission). **Do NOT move input-required back to working on tail snapshots** (text/tool during a permission wait are completion frames of pre-wait tools — polluting the state caused 409s and stuck flows). Subscribe replay (`/ws/nexus`) returns ONLY the latest round + `first_id` cursor; older rounds paginate via `GET /api/nexus/{wid}/rounds?before_id=`. `_push_web` wraps payloads in `{"type":<type_>,"payload":...}` — monitor pushes MUST pass `type_="monitor"` (a double-wrap bug once made the frontend drop the entire live stream).
- MCP is Streamable HTTP + stateless: every client call does a fresh `initialize`.
- Online status is dynamic: workspaces with heartbeat older than 90s (`HEARTBEAT_TIMEOUT_SECONDS`) count as offline; plugin heartbeats every 30s. `workspace_disable` marks status=disabled; heartbeat does NOT revive a disabled workspace (only `workspace_enable` does). Task dispatch online-check uses the plugin WS registry (`ws_online`), NOT the heartbeat timestamp.
- DB is SQLite at `data/agent_swarm.db` (gitignored). For a clean slate, stop the server and delete the db. `server/db.py:init_db` self-migrates (adds columns, backfills plaintext `api_key` for legacy users — this invalidates their old keys; it DROPs legacy `help_requests`/`workspace_calls`/`nexus_events` tables).
- Config via `server/config.py`: env vars win over root `.env`. Notable: `AGENT_SWARM_DB`, `AGENT_SWARM_JWT_SECRET` (defaults to a dev secret — set before production), `AGENT_SWARM_PUBLIC_URL` (overrides the host-derived URLs in Agent Cards + install scripts), `AGENT_SWARM_CALL_TIMEOUT`.
- **Weixin ClawBot channel (2026-09-19, E2E verified 2026-09-20)**: `server/weixin/` mirrors `server/feishu/` structure but with a fundamentally different transport — Tencent iLink Bot API 2.4.6 (official, HTTP/JSON at ilinkai.weixin.qq.com, no SDK; protocol reference in D:\wangxu\work\weixin-ClawBot-API). Each user scans THEIR OWN WeChat account into a bot (weixin_logins table, one row per user; bot_token encrypted at rest via user apikey). The user chats with the ClawBot conversation that appears in their WeChat. GOTCHAS: (1) replies MUST carry the context_token of the user's latest inbound message — proactive pushes fail after long silence (we cache the last token per user in DB; after restart it is restored from DB; ret=-2 on push = stale → clear cache, waits for next inbound); (2) private chat ONLY (official ChatType=direct, no group routing); (3) NO cards/buttons — permission/question are rendered as numbered text options (1.允许一次/2.始终允许/3.拒绝 — **response is digits-only**: bare digits answer pending, digit > 3 or non-digit = 允许一次; a pending task tops ALL other routing incl. menu, even `/q` answers it), inbound text routes to the pending task first (reply_task_from_feishu is reused, it is generic despite the name); (4) ret/errcode=-14 = token expired → session marks need_relogin, user must re-scan on the account page (QR flow: get_bot_qrcode → get_qrcode_status with need_verifycode pairing codes and scaned_but_redirect node switching); (5) getupdates is a 35s long-poll with a get_updates_buf cursor that must be persisted (we store it in DB per user); (6) outbound message_state is always 2 (FINISH) — typewriter streaming (GENERATING) was explicitly rejected by the user; (7) tool calls use plain text lines (`🔧 bash \`cmd\` ✓/✗`) — official tool_call items (type 11/12) were dropped after real-device testing showed normal WeChat client doesn't render them (gateway.send_tool_items kept unused); thinking is plain text (`💭`) in monitor mode; (8) commands: `/q`/`/swarm` = menu, `/swarm select|list|status|last`, `/swarm monitor on|off`, `/swarm brief on|off`, `/time`, `/重新连接`, `/1-/7` menu answers — **no `/swarm bind`** (weixin binds via QR scan on the account page, one account per user, no key needed); (9) login QR is a liteapp URL rendered to PNG via `qrcode[pil]` (deps.txt already has qrcode); (10) menu rule is strictly slash+digit or bare digit; unrecognized `/cmd` also returns the menu.
- **Cross-channel permission/question answering (2026-09-20, first-answer-wins)**: when the TUI (monitor round) raises permission/question, ALL nexus channels receive a card IF brief mode is on — web (native), feishu (`feishu/perm_card.py` now accepts kind-less flat monitor payloads via `from_monitor=True`; `_input_data` falls back to the flat payload shape), weixin (`bridge.py` monitor branch `permission/question` → `_push_monitor_input_required`, `replied` → `state.pop_pending_task`). Whoever answers first flips the task out of input-required; later replies fail cleanly per channel. Plugin dedupes permission/question by **request id** (`inputSeen` set per monitor round + `a2aInputSeen` for A2A rounds), NOT by single-value state — a second permission.asked after a TUI reject/answer has a NEW id and must be re-reported (live bug 2026-09-20 00:54: second permission popped in TUI but was swallowed). `state.set_pending(uid, task_id, kind, question, opts, request_id)` stores the REAL permissionId — replying with a bogus request_id (f"wx-...") left the TUI dialog hanging until timeout (bug 2026-09-20). Monitor-round task rows in `a2a_tasks` have id=roundKey, so the same reply endpoint (`reply_task_from_feishu`, task_id=roundKey, requestId) serves web+feishu+weixin.
- **opencode permission events have NO `title`** — the actual file paths/commands live in `patterns[]` (EventPermissionAsked). Plugin reports them in BOTH a2a input-required and monitor permission payloads; weixin card shows `访问/执行：<patterns>` and feishu perm_card permission-line shows them too. Without patterns the weixin card falls back to the round's user instruction (misleading, fixed 2026-09-20).
- **Encryption at rest (2026-09-19)**: optional; on when `AGENT_SWARM_ENC_KEY` is set (server/crypto.py). Encrypted columns: `workspaces.purpose_enc/notes_enc/session_title_enc`, `a2a_tasks.message_enc/artifact_enc/error_enc`, `a2a_events.payload_enc` (nullable Text). Sub-key = sha256(server_key + ':' + user_api_key) — per-user; the DB file alone is useless. Ciphertext format `enc1:<fernet>`. WRITES store ciphertext and CLEAR the plain column (when disabled, plain only). READS always go through `crypto.decrypt(key, enc, plain_fallback)` which falls back to the plain column — key loss makes history unreadable but nothing crashes. `init_db` backfills existing plaintext in place and clears plain columns (external tasks have no owner and stay plaintext). apikey reset (`/api/me/apikey/reset`) re-encrypts all of that user's rows via `_reencrypt_user_rows` — don't skip it or history becomes unreadable. `AGENT_SWARM_ENC_KEY_RECOVERY` is a second server key tried at decrypt time (rotation/loss recovery).
- `teams`/`team_members` tables remain in `server/models.py` but the feature was removed (API + web gone). Don't wire them back without asking (user chose to KEEP them, 2026-09-12).

## Plugin facts / gotchas
- **opencode V2 支持 (2026-09-23, 实测 2.0.15)**: V1 插件实现**不在 V2 运行**（官方明确），入口改为 `Plugin.define({ id, setup(ctx) })`（`@opencode/plugin`）。插件由**后台 service** 加载，`opencode run` 只是客户端（所以 V2 后台模式不需要 V1 的 `--pure`，该标志也已删除）。**V2 加载规则**（安装脚本据此）：`plugins` 条目必须是**目录的纯路径字符串**（指向文件的 `file://` 报 `configured plugin path must be a directory` 被丢弃）；目录要有**根 `index.ts`**（V2 发现规则，不读 package.json exports/main）；插件应**自包含**（不要运行时 import `@opencode/plugin`，只用 `import type`）——详见下面「安装脚本分流」条。仓库结构：`plugins/opencode/index.ts`（V2 包入口，转发 `src/v2/index.ts`）+ `src/v2/{index,background}.ts`；V1 的 `src/index.ts`/`src/tui.ts` 不动，安装脚本按 `opencode --version` 分流。
- **V2 事件模型 (2026-09-23)**: `ctx.event.subscribe()` 是**全局事件流**——同一 service 里每个 location 的插件实例都会收到所有 location 的事件，必须按 `event.location.directory` 过滤（否则给 A 项目的任务会注进 B 项目的前台会话，实测 bug）；`session.execution.*` 等事件可能**不带 location**，此时只接受本实例已知的会话（任务轮/监控轮/当前会话）。事件是**强类型命名事件**，不是 V1 的 `message.part.updated`：`session.inbox.enqueued`（`item.payload.text` 自带提问文本）、`session.text.delta/ended`、`session.reasoning.delta/ended`、`session.tool.input.started`（带 `name`）/`called`/`success`/`failed`、`session.execution.succeeded/failed/interrupted`（**收尾信号**，非 `session.idle`）、`permission.asked`、`form.created`、`session.error`。
- **opencode 安装脚本分流 (2026-09-23)**: `install-opencode.sh|.ps1` 先探测 `opencode --version`（major >= 2 → V2，否则 V1），**单向覆盖**、不共存。V1 分支保持原行为（`plugin` 数组 file:// + `tui.jsonc` + `mcp["agent-swarm"]` + 链接依赖）；V2 分支：**不装依赖**、**不写插件配置**（靠自动发现 `<config>/plugins/<name>/{index.ts,tui.ts}`）、MCP 写 `mcp.servers["agent-swarm"]`（V2 用 disabled 反向）、并清理另一版本留下的指向本插件的条目。**V2 插件刻意不 import 任何运行时裸模块**：`@opencode/plugin` 只做 `import type`（`define` 实测是恒等函数，直接导出对象即可）——配置目录下的插件在 opencode 加载器里**解析不到** `@opencode/plugin`（在插件目录或 `<config>/node_modules` 装都没用），去掉裸导入后才能真正自动发现加载。
- **V2 ctx 能力边界 (2026-09-23)**: `ctx.session` 只有 create/get/context/prompt/generate/command/synthetic/interrupt/update/move/wait/switchAgent/switchModel（**无 `list`** → 会话靠事件跟踪；**无 `form`**）；权限用 `ctx.permission.reply({ sessionID, requestID, decision: "once"|"always"|"reject" })`。**提问（V2 改为 form）在 server 插件无法应答**（只有 TUI 插件有 `session.form`）——用户决策 2026-09-23：V2 只上报不回答，后续按 V2 兼容问题反馈官方。注意 V2 的 `ctx.session.prompt` 会等到**整轮结束**才 resolve，任务轮必须在注入**前**就标记已开始，否则收尾时判断不到。

- **Installer structure (2026-09-13)**: `deploy/install.sh|.ps1` are dispatchers only; per-agent logic lives in `plugins/<name>/install-<name>.sh|.ps1` (dispatch passes `--server/--api-key/--src`). The tarball contains the whole `plugins/` tree — `deploy/start.*` tarballs `-C . plugins` (not `-C plugin`).
- **ps1 encoding**: Chinese-containing ps1 scripts that get **executed as local files** (the per-plugin installers, copied out of the tarball) MUST be saved UTF-8 **with BOM** — PS 5.1 reads BOM-less files as ANSI and Chinese bytes then eat quotes/newlines, breaking parsing (verified failure mode). The dispatcher `deploy/install.ps1` also has BOM now (local execution), but the server's `/download/install.ps1` endpoint strips it via `read_text(utf-8-sig)` so `irm | iex` stays safe.
- `plugins/opencode/src/config.ts` `loadConfig()` only reads `~/.config/opencode/agent-swarm.json` (or env `AGENT_SWARM_SERVER`/`AGENT_SWARM_API_KEY`); install scripts write both that file and `plugins/agent-swarm/config.json`.
- `/swarm-add` (and `/swarm-register`, `/swarm-remove`, `/swarm-enable`, `/swarm-disable`) are **not** registered by the plugin: they are markdown files in `plugins/<name>/commands/` copied to `~/.config/opencode/commands/` (opencode) or `~/.claude/commands/` (claude) by install scripts. To change command behavior, edit the source md in the repo and reinstall — don't inline command text in install scripts. claude copies use `mcp__agent-swarm__*` tool naming in the md body.
- The opencode plugin runs on the user machine, not in this repo: after editing `plugins/opencode/src/`, reinstall locally via the one-liner printed on the web install page (server must be restarted first so start.ps1/start.sh rebuilds the tarball).
- **IMPORTANT: after changing `plugins/opencode/src/`, the running opencode sessions still hold the OLD plugin code** — a reinstall + opencode restart is required before any E2E test. ALWAYS notify the user and wait for them to restart opencode before running end-to-end tests; don't fire test calls and wonder why nothing happens (the plugin.log shows which version is actually loaded).
- **Task injection is foreground-first** (user decision 2026-09-12): target = event-hook-tracked current session (cold start: `session.list` picks most recent + `tui.showToast` notice); if fgBusy or target session busy (`session.status`), queue-wait up to 10 min; background `session.create` only as last resort. Completion = `session.idle` event + 2s polling fallback; stuck-on-tool-call gets synthetic nudges (≤2).
- **A2A event mapping in the plugin** (`nexus_a2a.ts` + `index.ts`): opencode SSE parts → `status-update` events with `metadata.nexus` = `text`/`reasoning`/`tool` (part-id keyed, web merges streams); `permission.asked`/`question.asked` → `input-required` status with a DataPart (`{type, requestId, ...}`); `session.idle` → extract last assistant text → `artifact-update` (lastChunk, full text) + `completed`. input-required replies come back as `message/send` continuations whose parts contain `kind: "data"` — `onReply` routes them to the opencode permission/question APIs.
- **Monitor pipeline (2026-09-15)**: the event hook is a SINGLE pipeline — `sessionID ∈ a2aRuns` → task events (existing path, unchanged); else foreground session (`sid === currentSessionId`) and `monitor` config on (default ON, `/swarm-monitor` toggles, hot-reloaded per event) → `monitorEmit`. Round lifecycle: `message.updated`(role=user, new msgID) opens a round (roundKey=`mon-<sid8>-<msgId12>`) → parts stream → `session.idle` closes it. GOTCHAS: (1) `message.updated` info has NO parts — emit empty `user` event then backfill text via `session.messages` as a `user-text` event; (2) the user's own message also emits `text` parts — skip parts whose messageID === round.userMessageId or the question renders as an answer; (3) monitor event field names are camelCase (`callId`/`partId`/`toolState`) — the web reader must match or keys collide and rounds collapse to the last item (verified bug). Reply path: DataPart now carries `taskId` (roundKey for monitor rounds); after answering, plugin emits a `replied` monitor event so the server can exit input-required.
- **claude keepalive lifecycle**: `claude mcp list` health checks also spawn/exit the keepalive process (stdin-close exit is by design). Multiple claude sessions on one project → multiple keepalives heartbeating the same workspace, harmless (server-side idempotent). `claude mcp list` output format is `name: ... - ✔ Connected` — idempotency checks in install-claude must match `name:` (with colon).

## Web facts / gotchas
- Frontend is user-facing: docs page (`web/src/App.tsx` `DocsPage`) intentionally contains NO server-deployment content — the user is already looking at a running deployment. Keep it that way.
- Video `web/public/agent_swarm.mp4` (~39MB) is committed as a regular blob (user accepted; LFS considered and skipped for now). Autoplays once muted when scrolled into view, stops on last frame, no controls.
- Results in call records render as markdown (react-markdown + remark-gfm) — task prompts ask agents to summarize in markdown-friendly prose.
- Auth UX: logged-out visitors see Home/Docs only + a login *modal* (not a page); protected nav items hidden. Account page (click username) has a left sub-menu: API Key | change password.
- **Workspace selection UI: ALWAYS use `NexusWorkspaceSelect`** (App.tsx exported component) — never a raw `<select>`. Applies to every workspace picker in web pages (Nexus, account chat-bind cards for Feishu/WeChat, admin, …): it carries the unified look (search, agent-type icon, online hint) the user expects (user decision 2026-09-20, after a raw select slipped into the chat-bind cards).

## Conventions
- Comments and handoff notes are in Chinese; keep new ones consistent (TODO.md is the running handoff doc — read it before starting work).
- **NEVER merge to `master` unless the user explicitly asks** (user decision 2026-09-23): work and commit on `dev`; `master` merges are user-triggered only. Don't "顺手" push a dev→master merge.
- **Never `await` (or `yield`) inside a `with Session(engine)` block** (2026-09-23 connection-pool freeze incident): SQLite `QueuePool` is tiny; a session held across an await blocks a pool connection, and once the pool is exhausted the *synchronous* checkout blocks the event loop — the whole service freezes (even `/health`). Pattern: open a short session → do sync reads/writes → capture a field snapshot → close → then await (network/WS/long waits) → reopen a short session for the result. `db.py` runs WAL + `busy_timeout` + a 30-conn pool as a safety net, not an excuse. Note `with Session` does NOT auto-commit — any `_mark_task`-style mutation needs an explicit `session.commit()`.
- **Timestamps are UTC everywhere** (DB `created_at`/`last_heartbeat`, server logs, plugin.log ISO strings) while the user is in Beijing time (UTC+8) — a "fresh" timestamp looks ~8h stale at a glance. Do NOT judge heartbeat freshness by eyeballing vs local clock; compare against `now - 90s` in UTC or just trust `ws_online` (see Online status below). This trap has caused repeated misdiagnosis (2026-09-14).
- Revise files with the edit tool directly; never edit files via ad-hoc scripts (PowerShell regex pipelines, `python -c` rewrites). Scripts for file mutation are hard to review and have caused broken edits here.
- No CI, no pre-commit hooks, no codegen.
